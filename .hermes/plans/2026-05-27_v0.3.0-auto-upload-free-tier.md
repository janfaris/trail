**Date:** 2026-05-27
**Status:** Plan
**Author:** Hermes (orchestrator) + Jan
**Estimated build time:** ~1 day (CLI side) + ~half day (web/quota gates)

---

## Goal

Two things shipped together so the "frictionless cost-per-PR" pitch finally
becomes literal:

1. **Auto-upload**: daemon uploads anonymized sessions to gettrail.vercel.app
   when their linked commit lands on `origin/main`. No manual `trail share`.
2. **Free-tier scope**: 30-day rolling history, 200-session cap, 1 BYOK
   vendor. Paid Pro ($19/mo) and Team ($49/seat) unlock the rest.

Free-tier launch must be cheap to serve so non-converting users don't bleed
margin. Cost-budgeted below.

---

## Constraints

- Default behavior stays **consent-preserving**: `autoUpload=false` until
  the user opts in. Never silently uploads from `npm install`.
- Anonymization + entropy guard run BEFORE every upload. Same redactor +
  same guard the manual `trail share` flow uses today. Zero shortcut.
- Local capture stays unlimited and zero-network — only **upload** is
  gated. The daemon never refuses to ingest.
- Free tier cost ceiling per user: **< $0.10/month** in Neon + Vercel.
  Hard cap means 1,000 free users = ~$100/mo serving cost, viable on Pro
  plan. See cost analysis below.

**Why 30 days + 200 sessions:**
- 30 days covers "what did I spend this month?" — the primary review cadence
  most devs run.
- 200 sessions is roughly **10 hard-working coding days** for a typical
  indie dev (5–20 sessions/day). Power users hit the wall first → those
  are exactly the segment that converts.
- Sessions outside the window aren't deleted, just hidden from rollups.
  Re-subscribing surfaces them again — recoverable, not punitive.

## Cost Analysis (free tier)

Sized for **1,000 free users** as a first checkpoint.

### Neon storage

| | Per user | × 1,000 users |
|---|---|---|
| Sessions stored | 200 max | 200,000 sessions |
| Avg session size (compressed JSONL in Neon) | ~50 KB | 10 GB |
| Plus events, indexes, attribution rows | +30% | ~13 GB |

Neon Pro: 10 GB included + **$0.50/GB-month** overage. 13 GB = **$1.50/mo
overage**. Per-user storage cost: **$0.0015/mo**. Negligible.

### Vercel functions

| | Per user/month | × 1,000 |
|---|---|---|
| Page views of `/dashboard/cost` | ~30 | 30,000 |
| Upload route invocations | ~200 (one per shipped session) | 200,000 |
| Cron + admin sync | n/a (server-shared) | shared |

Vercel Pro: 1M function invocations/mo included, then **$0.40/M**.
230k for 1k users → free. Headroom to **~4,000 free users** before paying.
Per-user function cost at scale: **~$0.0001/mo**.

### Vercel bandwidth

Dashboard pages ~30 KB rendered HTML × 30 views = **~1 MB/user/month**.
Vercel Pro includes 1 TB. Free tier all 1k users = 1 GB. Negligible.

### Total free-tier serving cost

| | Cost / user / month |
|---|---|
| Neon storage | $0.0015 |
| Vercel functions | $0.0001 |
| Vercel bandwidth | ~$0.0001 |
| **Total** | **< $0.01/user/mo** |

**Headroom is ~10x what I budgeted.** 30 days × 200 sessions on free is
safe up to ~10,000 free users on current Vercel Pro + Neon Pro plans. By
the time we cross that, conversion revenue covers infra at 3–5% paid
rate.

**Implication:** ship **30 days history × 200 sessions cap** confidently.
If a power-user spikes (e.g. 2,000 sessions in a week), the cap protects
me automatically. No surprise bills.

## Implementation Plan (v0.3.0 CLI)

### Task 1 — Local config file

`apps/cli/src/lib/config.ts` (new file)

- Reads/writes `~/.trail/config.json`
- Shape: `{ autoUpload: boolean, autoUploadVerifiedOnly: boolean }`
- Defaults: `{ autoUpload: false, autoUploadVerifiedOnly: true }`
- Add CLI subcommand:
  ```
  trail config get [key]
  trail config set <key> <value>
  trail config list
  ```

### Task 2 — Daemon auto-upload loop

`apps/cli/src/commands/record.ts`

After each session is ingested into local DB, check:

1. `config.autoUpload === true` (else: skip silently)
2. Session has `linkedCommitSha` set (from git context capture)
3. Commit is reachable from `origin/main` (or repo's default branch).
   Run `git merge-base --is-ancestor <sha> origin/main`. Returns 0 if
   reachable. If unreachable (still on feature branch) → defer.
4. Session hasn't already been uploaded (`share_slug IS NOT NULL` in
   local DB).
5. Run existing `redactSessionForCapture()` + anonymize pipeline.
6. Run existing **entropy guard** (same as `trail share`).
7. On pass → POST to `/api/sessions/upload` with auth token. Store
   resulting `share_slug` back into local DB.
8. Log line to `~/.trail/daemon.log`:
   ```
   ✓ auto-uploaded 019e... → /u/jankarlo.faris/abc123 ($3.77, PR #23)
   — or —
   ✗ skipped 019e... — entropy guard hit pattern `sk-ant-...`
   ```

### Task 3 — Periodic re-check of unshipped sessions

A user might code on a branch, then push + merge two days later. Need to
re-scan unshipped sessions whose linkedCommitSha may now be reachable.

Add a **5-minute polling loop** inside the daemon:
- Query local DB for sessions where `share_slug IS NULL AND linked_commit_sha IS NOT NULL`
- For each, run the reachability check again
- On newly-reachable → run the upload pipeline

Cap: re-check at most 50 stale sessions per poll cycle to avoid runaway
fetch on a busy repo.

### Task 4 — Post-login prompt update

`apps/cli/src/commands/auth.ts` — extend the daemon-install prompt to
a 2-step flow:

```
Logged in as @jankarlo.faris
Start the background daemon now? (registers a launch agent so capture runs across reboots) [Y/n] Y
Installed com.trail.daemon
Auto-upload shipped sessions to your dashboard? (entropy-guarded; you can flip this later via `trail config set autoUpload`) [y/N] Y
✓ Auto-upload enabled. Sessions ship to /u/jankarlo.faris when their PR merges.
```

Default for question 2 is **N** (consent-preserving). User opts in
explicitly.

### Task 5 — Daemon status surfaces auto-upload state

`trail daemon status` output becomes:

```
running (pid 12345) · auto-upload ON · last uploaded 3m ago (slug abc123)
```

or

```
running (pid 12345) · auto-upload OFF · run `trail config set autoUpload true` to enable
```

### Task 6 — Web: quota enforcement

`apps/web/app/api/sessions/upload/route.ts` — gate uploads by tier:

1. Look up user's plan (free / pro / team) from `user.plan` column
2. For free users:
   - Query count of sessions uploaded in last 30 days
   - If >= 200 → return `409 quota_exceeded` with structured error:
     ```json
     {
       "error": "free_tier_session_cap",
       "message": "Free tier stores up to 200 sessions per 30 days.",
       "upgrade_url": "https://gettrail.vercel.app/pricing",
       "current_count": 200,
       "limit": 200
     }
     ```
3. Pro/Team users: no cap.

CLI surfaces the 409 cleanly:
```
✗ Free tier cap reached: 200 sessions in 30 days.
  Upgrade at https://gettrail.vercel.app/pricing — or sessions
  outside the 30-day window will roll off and free up slots.
```

### Task 7 — Web: dashboard window filter

`apps/web/app/dashboard/cost/page.tsx` — when `user.plan === 'free'`:

- Date filter forced to last 30 days (no 90d option visible)
- Banner above table: "Free tier — 30-day rolling window. **See lifetime
  cost-per-PR** with Pro →"
- Sessions still load if older than 30 days but aren't included in rollups

### Task 8 — Stripe wiring (defer until paywall is up)

This block stays as a follow-up after v0.3.0. The plan above only enforces
client-side and via the upload route; Stripe checkout + plan flip lives in
the existing `apps/web/app/api/billing/*` routes that need price-ID
verification before going live.

For v0.3.0 ship, all users default to `plan='free'`. Pro/Team flips
manually via DB until Stripe is verified.

| Fresh install → `trail login` → say N to both prompts | Daemon not installed, autoUpload off. Nothing uploads. |

## Risks & open questions

- **Entropy guard false negatives**: a session might slip through with a
  secret. Mitigation: keep the receiptStatus="draft" state on auto-uploads
  AND require a per-session "publish to public profile" toggle (default
  off). Auto-upload populates the dashboard but doesn't make the session
  HTML-viewable by the public until explicit publish. *Worth one more
  round of design before code.*

- **Free user blast radius from a runaway daemon**: someone forks
  Trail's repo and runs `trail record` in a CI loop, uploading 10k sessions
  in an hour. The 30-day rolling cap protects against storage; rate
  limit at upload route protects against bandwidth (add 100/hr/user).

- **Plan column drift**: if Stripe webhook for downgrade fails, user keeps
  paid features for a day. Acceptable for v0.3.0; cron reconciliation in
  v0.3.1.

- **PR auto-link still requires `public_repo` OAuth scope**: existing
  v0.2.0 user accounts may have signed in before #25 widened scope.
  Auto-upload code path checks `accessToken` exists; if not, falls back
  to "uploaded without PR link" — session shows on dashboard with empty
  PR column, not a hard failure. Re-sign-in fixes it.

## Definition of done

A new visitor lands on gettrail.vercel.app:
1. Sees the $3.77 hero
2. Runs `npm install -g @gettrail/cli`
3. Runs `trail login`, says Y to both prompts
4. Codes for a day with Codex

Zero manual `trail share`. Zero admin keys. Free tier holds them up to
